2 — /checkpoint, codes match

Local output, never sent to the relay. Two design decisions worth arguing about: the code is grouped into two 4-char halves so it survives being read aloud over a phone call, and the line under it names the window explicitly — the chain only covers retained history after eviction (design doc, Open Question 1).

3 — Chain broken

The failure state is the whole point of the feature, so it gets the loudest treatment: status bar flips, the transcript is marked at the exact break, and the message says what to do rather than what happened. Deliberately does NOT say "you are being attacked" — a relay restart or an eviction-boundary bug produces the same signal.

4 — Create flow (amendment A5)

Premise 3 says confidentiality against the relay operator equals password strength, so the generated passphrase is the default path, not the fallback for an empty prompt. Pressing Enter accepts it; typing is the deliberate act. This inverts spec §6.1.
